# Telegram

Что делает мост: голосовое из Telegram попадает в очередь «не прослушано» и играет на колонке платы по кнопке; запись с платы
уходит вам в Telegram.

## Настройка

1. В @BotFather создайте бота. Токен храните **только** в `telegram.json` рядом с программой (пример: `config/telegram.example.json`).
   В чат, почту, репозиторий токен не вставляйте. Если токен где-то показали, перевыпустите: @BotFather → `/mybots` → бот → API Token → Revoke.
2. Скопируйте `config/telegram.example.json` в `telegram.json` рядом с `mic_server.exe`, впишите токен, `chat_id` оставьте `null`.
3. Запустите сервер и напишите боту любое сообщение. Бот ответит вашим числовым ID.
4. Впишите ID в `chat_id`, перезапустите сервер. С этого момента бот отвечает только этому чату, остальным молчит.

## Группа с топиками

Если бот работает в группе-форуме, записи можно отправлять в один топик и принимать голосовые только из него:

1. Откройте нужный топик и отправьте боту команду `/id`. Бот ответит `Чат: … Топик (TELEGRAM_THREAD_ID): …` (команда работает из любого топика).
2. Впишите значения в `.env`: `TELEGRAM_CHAT_ID` и `TELEGRAM_THREAD_ID`, перезапустите сервер.
3. С этого момента записи с платы приходят в этот топик, а голосовые из других топиков группы сервер игнорирует.

Группа это не личный чат: все её участники могут присылать голосовые на плату и видят записи. Для личного канала пишите боту в личку (ID положительный).

## ffmpeg

Голосовые в Telegram это OGG/Opus. Для перекодировки нужен ffmpeg: положите `ffmpeg.exe` в папку `ffmpeg/` рядом с программой
или задайте переменную `FFMPEG`. Без него бот принимает WAV и присылает записи обычным файлом.

## Безопасность

Бот обслуживает один `chat_id`. Пока `chat_id` не задан, бот только сообщает ID и ничего не сохраняет. Ошибки Telegram в журнале
не содержат токена.
