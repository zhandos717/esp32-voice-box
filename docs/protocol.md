# Протокол плата ↔ сервер (TCP, порт 8800)

Начало соединения: плата отправляет 10 байт: `MIC2`, частота дискретизации (4 байта, LE), разрядность (2 байта, LE).
Сервер закрывает соединение, если заголовок другой (старая прошивка).

Разрядность `4` означает, что плата понимает IMA ADPCM: тогда звук в обе стороны идёт сжатым в 4 раза (8 КБ/с вместо 32 КБ/с).
Звук передаётся независимыми блоками: первый отсчёт (int16, LE), индекс шага (1 байт), n = число байт данных (1 байт),
затем n байт = 2n отсчётов, сначала младшая тетрада. Кодек: `server/adpcm.go` и `firmware/mic_stream/adpcm.h`.

## Плата → сервер

Кадр: 1 байт тип, 2 байта длина (LE), данные.

| Тип | Значение | Данные |
|---|---|---|
| 1 | звук, 16 кГц, моно | PCM 16 бит или один блок ADPCM (разрядность 4) |
| 2 | кнопка записи нажата | нет |
| 4 | кнопка записи отпущена | нет |
| 3 | кнопка «следующая запись» | нет |
| 5 | отладочный текст | текст |

Запись идёт, пока кнопка удержана. Если между нажатием и отпусканием меньше 0,3 с, запись отбрасывается. Плата хранит последние
0,4 с звука и отправляет их в начале записи, чтобы не терять начало фразы. Предел длины одной записи: 300 с (`MIC_MAX_SECONDS`).

## Сервер → плата

| Байт | Значение |
|---|---|
| `R` | начать отправку звука |
| `S` | остановить |
| `U` + число | сколько записей не прослушано (светодиод) |
| `N` | нечего проигрывать |
| `P` + длина (4 байта, LE) + PCM | проиграть запись на колонке |
| `A` + длина (4 байта, LE) + блоки ADPCM | то же, сжатое (плате с разрядностью 4) |

## Очередь «не прослушано»

Записи: `rec_ГГГГММДД_ЧЧММСС.wav` (с платы), `tg_….wav` (из Telegram). Порядок по метке времени в имени. Что уже проиграно,
хранится в `recordings/played.json`. Запись считается прослушанной, когда её отдали на плату или включили в браузере.

## Веб-интерфейс (только 127.0.0.1:8801)

`GET /` страница · `GET /api/status` · `GET /api/list` · `POST /api/start` · `POST /api/stop` · `POST /api/mark/<имя>` · `GET /rec/<имя>.wav`
